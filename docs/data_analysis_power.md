# DAAgent 数据分析能力建设

## 一、产品定位

构建一个能够自主完成专业数据分析，并持续学习、沉淀和复用企业分析工作方法的 AI Agent。

核心能力包括：专业分析、自定义专家、工作方法学习、历史经验复用和分析结果验证。

## 二、整体技术架构

用户交互层

自然语言交互 · 数据上传 · 专家管理 · 分析报告

专家能力层（Expert System）

内置专家 · 自定义专家 · Skills · 业务知识 · 方法组合

统一 Agent 运行时

Planner · AgentLoop · Harness · ToolRegistry · AgentState

经验学习与方法复用层

Memory Engine

Method Learner

Method Retriever

Method Validator

工具与知识资产层

Python / SQL · 统计工具 · 企业知识库 · 方法库 · 历史分析资产

## 三、核心功能规划

| 模块         | 核心功能                                         |
| ------------ | ------------------------------------------------ |
| 通用 Agent   | 自主规划、工具调用、数据处理、统计分析、结果交付 |
| 专家系统     | A/B 测试、漏斗分析、指标诊断等专业专家           |
| 自定义专家   | 用户通过自然语言、SOP、知识库和模板创建专家      |
| Skills 系统  | 封装专业分析方法，支持动态加载与组合             |
| 记忆系统     | 保存用户偏好、业务知识、项目上下文与分析经验     |
| 方法学习引擎 | 从任务执行和用户反馈中提取可复用工作方法         |
| 方法复用引擎 | 根据任务语义和适用条件检索、加载历史方法         |
| 评测与验证   | 检查统计正确性、方法适用性、证据完整性和执行效果 |

## 四、重点建设：工作方法学习与复用

01

执行分析任务

记录分析目标、执行步骤、工具调用及用户反馈

02

提取工作经验

识别可复用的分析流程、业务规则和用户偏好

03

生成 MethodSpec

将经验转化为结构化工作方法，描述步骤、适用条件和依赖

04

方法验证与存储

经专业校验和必要的用户确认后，保存为可版本化方法

05

智能检索与复用

后续任务自动匹配适用方法，由 Agent 灵活规划执行

06

持续优化

根据执行效果和用户反馈改进方法，支持版本回退

方法学习采用三种机制：用户显式保存、用户反馈驱动、历史任务自动归纳。初期优先实现显式保存和方法复用，自动归纳作为后续增强。

## 五、专家与方法的协作机制

专家不绑定固定的分析流水线，而是动态组合以下能力：

`ExpertSpec + Skills + MethodSpec + Knowledge + Tools`

- ExpertSpec： 定义专家定位、职责、工作偏好及输出规范。
- Skills： 提供专业知识、分析方法和操作指导。
- MethodSpec： 保存可以跨任务复用的工作步骤、条件和验证要求。
- Knowledge： 提供企业指标口径、数据字典、SOP 等业务信息。
- Tools： 执行真实的数据处理与统计计算。

系统根据当前任务和数据条件选择合适的能力，允许调整分析路径，但保留必要的专业验证和平台安全约束。

## 六、分阶段开发计划

| 阶段          | 建设内容                                   | 阶段成果                 |
| ------------- | ------------------------------------------ | ------------------------ |
| P0 基础核验   | 核验现有代码、统一运行时与接口             | 稳定的开发基线           |
| P1 专家框架   | ExpertSpec、专家注册、动态加载、版本管理   | 支持内置专家运行         |
| P2 专业能力   | A/B 测试专家、统计 Skills、验证工具        | 完成专业分析任务         |
| P3 自定义专家 | 自然语言配置、SOP、知识与模板绑定          | 用户能够创建自己的专家   |
| P4 方法复用   | MethodSpec、方法保存、检索、匹配与加载     | 跨任务复用分析方法       |
| P5 经验学习   | Memory Engine、Method Learner、反馈归纳    | 从历史任务中提取候选方法 |
| P6 平台增强   | 专业评测、方法优化、团队共享、可选专家协作 | 持续积累企业分析资产     |

## 七、首期 MVP 范围

建议第一阶段集中实现一个完整闭环：

A/B 测试专家 → 用户自定义分析流程 → 完成实验分析 → 保存工作方法 → 后续任务自动复用。

首期重点验收：

1. 能够完成 A/B 测试的专业分析与必要检查。
2. 用户能够自定义专家的分析流程和交付模板。
3. 能够把确认过的分析流程保存为 MethodSpec。
4. 新任务能够检索并复用合适的历史工作方法。
5. 分析结论可追溯，方法不适用时能够识别并提示。

首期不必实现多专家协作、自动生成执行代码的 Skills、复杂可视化工作流编辑器。

## 八、核心设计原则

专业性： 专业统计方法与真实计算工具相结合，而非单纯依靠提示词。

灵活性： 工作方法是可调整的分析指导，不是所有场景都必须执行的固定流水线。

可学习： 从用户确认的历史经验中积累能力，不将未经验证的结论自动转化为规则。

可复用： 分析方法与专家解耦，支持跨专家、跨项目复用，并控制用户及组织的数据访问权限。

可验证： 方法、数据口径、计算过程、分析证据和版本均可追踪。

最终建设目标：

让 DAAgent 逐步形成 专业分析能力 → 用户自定义 → 工作经验沉淀 → 智能复用 → 持续优化 的完整闭环，使其从一次性数据分析工具发展为可持续积累企业专业知识和工作方法的智能分析平台。

本计划为目标方案，具体模块的实现程度仍需以实际代码核验为准。
