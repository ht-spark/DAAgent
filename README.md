# DAAgent（数据分析智能体）

> 面向产品经理 / 数据分析师的端到端业务分析平台 — 自动理解问题、清洗数据、探索验证、产出报告 + RAG 知识库头脑风暴

DAAgent 把「理解问题 → 理解与清洗数据 → 探索与验证 → 产出洞察与报告」这一复杂人工分析流程，自动化为一个可监控、可干预、可复现的系统。平台由两大核心能力构成，并通过 FastAPI 服务层与 React 前端集成：

| 能力              | 角色                                                   | 典型场景                                         |
| ----------------- | ------------------------------------------------------ | ------------------------------------------------ |
| 分析任务（Agent） | 从业务问题 + 明细数据到完整分析报告的端到端求解引擎    | 「上周活跃为什么下降」「上线后转化是否真的提升」 |
| 业务知识库 RAG    | 基于私有文档的检索增强问答，对齐指标口径、复用历史结论 | 分析前头脑风暴、指标口径核对、历史经验复用       |

两者共享同一套 LLM 配置与文件存储基础设施；规划中将打通「知识库引导分析、报告回灌知识库」的闭环。

## 1. 功能介绍

### 1.1 功能一：分析任务（智能体求解）

提交一个业务分析问题并附上数据文件，系统自动产出完整分析报告（Markdown/DOCX），包含图表、结论、中间代码与数据。

**你能做什么：**

- 提交自然语言分析问题（直接粘贴文本，或上传 `.md`/`.txt` 问题描述文件）。
- 附加数据文件（CSV/Excel/JSON/Parquet 等，可多个）。
- 选择/配置大模型（OpenAI、DeepSeek 或自定义 OpenAI 兼容 endpoint）。
- 在运行中**人工介入**：回答澄清（主键、时间范围、成功指标）、调整每问预算、取消任务。
- 获取**完整产物包**：分析报告（Markdown / DOCX）、图表、表格、中间代码与清洗后数据，以及审查报告。

**端到端流程：**

```
提交问题+数据 → Phase1 数据画像+问题理解 → 信息是否充分(G0)?
  ├─ 否 → 弹出澄清请求 → 你补充材料/终止
  └─ 是 → 逐层分析 → 自动选型(问题类型+数据特征) → 生成分析代码并沙箱执行
       → 结果校验 → (不通过且可重试 → 重执行)
       → 全部子问题完成 → 撰写报告 → 自动审查 → (需修订 → 重写)
       → 通过/强制交付 → 最终报告 + 图表 + 中间产物
```

进度通过 SSE 实时推送（节点级 Phase 1 → Phase 6）。

**关键能力亮点：**

- **自动分析路径探索**：结合问题类型与数据特征，选择描述统计、对比分析、归因拆解、相关/回归、漏斗与留存等方法，避免「拍脑袋下结论」。
- **代码化分析**：LLM 生成 Python 分析代码并在隔离子进程执行，结果可复现。
- **按问题类型校验**：描述/对比/归因/预测/漏斗/异常检测等分别有对应的验证规则（样本量、混杂因素、显著性、业务合理性）。
- **可追溯报告**：报告章节与证据、决策日志、各子问题结论一一对应，关键数字可回溯到中间表。
- **三道质量门**：G0 摄入门、GQ 逐问门、GF 交付门，并支持子问题预算控制。

**产物清单：**

- 分析报告（`paper.md` / `paper.docx` 或等价 Markdown/DOCX）
- 图表（趋势、对比、分布、漏斗、留存、相关性等）
- 表格（汇总统计、分组结果、显著性检验）
- 中间代码与清洗后数据
- 审查报告（数据质量、方法合理性、结论风险）
- 结构化运行日志（`run.log` JSON：节点耗时、token、工具调用）

### 1.2 功能二：基于 RAG 的业务知识库与头脑风暴

构建本地知识库，与「读过这些资料的 LLM」对话，帮助对齐指标口径、复用历史结论与分析框架；形成的约束与思路可体现到后续分析任务中（深度集成见路线图）。

**你能做什么：**

- 上传业务文档（PDF/DOC/DOCX/PPT/PPTX/PNG/JPG/Markdown/TXT，或含上述文件的 ZIP）。
- 将非 Markdown 文档经 **MinerU** 转换为 Markdown（公式、表格可识别）。
- 一键**分块 + 向量化**，建立本地检索索引；可删除文档并同步重建索引。
- 在「头脑风暴」中提问，获得**带引用出处**的回答（指标口径、历史结论、分析框架）。
- 查看历史讨论、文档清单、切片数量与知识库统计。

**使用流程：**

```
上传文档/ZIP → 归档到 raw → {是 Markdown?}
  ├─ 否 → MinerU 转 Markdown → documents/*.md
  └─ 是 → documents/*.md
→ 分块+嵌入→ Qdrant → 知识库就绪 → 头脑风暴提问
→ 混合检索 + 重排 → LLM 回答 → 返回答案 + 来源引用
```

**检索能力说明：**

- **混合检索**：稠密（BGE 语义向量）+ 稀疏（BM25 关键词）双路召回。
- **RRF 融合**：两路排名倒数融合后取最相关片段。
- **重排序**：Cross-encoder 精排 Top-K（架构层已规划；当前链路以混合检索为主）。
- **可选 LLM 压缩**：传入 LLM 时对候选做上下文压缩，去除冗余噪声。
- **引用溯源**：每个回答附带 `source_file`（来源文档）与原文片段，便于核对。

**管理操作：**

- 管理历史文档上传记录；管理灵感讨论历史对话，可继续聊天或删除（网页与本地记录同步删除）。

### 1.3 两功能的协同（设计目标）

- 将知识库中的指标口径、业务约束与历史结论直接加载进分析智能体，引导其选型与解读。
- 将每次任务产出的报告回灌知识库，形成「越用越聪明」的闭环。

## 2. 面向群体

| 用户类型       | 典型画像                         | 核心诉求                                 |
| -------------- | -------------------------------- | ---------------------------------------- |
| 产品经理       | 有业务问题，能看懂图表，少写代码 | 上传明细数据，快速得到可讲清的结论与图表 |
| 数据分析师     | 日常 ad-hoc 需求多，时间碎片化   | 自动完成清洗/探索/验证，缩短从提问到报告 |
| 业务运营/增长  | 关注转化、留存、活动效果         | 不写 SQL 也能拿到结构化洞察与行动建议    |
| 数据团队负责人 | 需要方法可复用、结论可追溯       | 统一分析规范，沉淀指标口径与历史分析资产 |

**核心使用路径：**

- **路径 A · 直接分析**：描述问题并上传数据 → 系统自动理解与清洗 → 逐层分析 → 产出报告。
- **路径 B · 口径先行**：上传指标字典/历史报告 → 头脑风暴对齐口径与框架 → 将约束写入任务 → 提交分析。
- **路径 C · 迭代追问**：跑任务 → 阅读报告与审查意见 → 补充数据或调整问题 → 再次提交。

## 3. 主要技术

### 3.1 设计原则

- **检索优先**：知识库回答基于真实文档内容，不依赖 LLM 参数化记忆。
- **Agent 自主决策**：LLM 自主决定是否检索、如何改写查询、检索几次、何时信息足够。
- **引用可追溯**：每个结论都能定位到源文档的具体片段或中间数据表。
- **现有代码零侵入**：复用知识库检索管线与建模/代码执行能力。
- **Loop / ReAct / Harness 分离**：决策与执行解耦，独立测试、独立演进。
- **LLM-only 策略**：不预设固定分析方法论，由 LLM 围绕具体问题与数据驱动全流程。

### 3.2 技术栈

| 层次              | 技术选型                                                                          |
| ----------------- | --------------------------------------------------------------------------------- |
| 编排              | LangGraph（`StateGraph` + `MemorySaver` 检查点）                              |
| Agent 决策        | Loop（Thought → Action）+ Harness 安全执行；ReAct 为 loop 内思考策略             |
| 大模型接入        | `langchain-openai`（OpenAI 兼容：OpenAI / DeepSeek / 自定义 endpoint）          |
| 结构化数据        | Pydantic v2                                                                       |
| 数值计算 / 可视化 | pandas, numpy, scipy, scikit-learn, matplotlib, pulp                              |
| 文档转换          | MinerU API（PDF/DOC/PPT/图片 → Markdown）                                        |
| 文本切分          | LlamaIndex`SentenceWindowNodeParser`                                            |
| 向量嵌入          | BGE-Small-Zh-V1.5（本地 HuggingFace，CPU 推理）                                   |
| 向量存储          | Qdrant（本地文件型，无需独立服务进程）                                            |
| 检索后处理        | `langchain-classic` `LLMChainFilter` 上下文压缩                               |
| 服务框架          | FastAPI + Uvicorn，SSE（Server-Sent Events）实时进度                              |
| 前端              | React + Vite + TypeScript（react-markdown + remark-math + rehype-katex 渲染公式） |

### 3.3 分层架构

```
web/ ──→ server/ ──→ agent/graph.py
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
         agent/loop  runtime/harness  memory/
         (决策)      (执行)           (记忆)
              │          │
              ▼          ▼
         agent/tools  runtime/sandbox
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
  rag/     scr/      tools/
  (检索)   (建模)    (代码执行)
```

| 目录/模块          | 职责                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| `agent/`         | 决策编排：Loop 决策、状态、查询改写/充分性自评 Prompt、工具 schema     |
| `rag/`           | 检索基础设施：摄入（加载→解析→分块→嵌入→入库）、混合检索、索引管理 |
| `runtime/`       | 运行时：Harness 执行、会话、检查点续跑、流式输出、沙箱、任务队列       |
| `gateway/`       | 模型网关：路由、降级、缓存、限流、计量                                 |
| `memory/`        | 工作/短期/长期/情景记忆                                                |
| `observability/` | 链路追踪、指标、结构化日志、面板                                       |
| `security/`      | 输入过滤、输出审查、知识库权限、审计                                   |
| `evaluation/`    | 回归测试、检索质量（Recall@K / MRR / NDCG）、忠实度评估                |
| `server/`        | FastAPI：对话、知识库、文件、管理接口                                  |
| `web/`           | 对话界面（引用标注 + 检索过程）、知识库管理、任务面板                  |

**边界说明：**

- `agent/` 只产出 Action，不直接执行工具；`runtime/harness.py` 负责权限、超时、沙箱与错误标准化。
- `rag/` 被 `agent/tools/retrieval_tools.py` 调用；建模/报告导出等能力按需包装现有 `scr/` 模块。
- `server/` 与 `web/` 只与 `agent/graph.py` 交互；`observability/`、`security/`、`evaluation/` 横切所有层。

### 3.4 非功能要点

- **性能**：提交到首次 SSE ≤ 2s；单子问题分析（含代码执行）≤ 8min（复杂可放宽）；知识库检索 ≤ 3s。
- **可靠性**：代码隔离子进程执行；支持断点续跑；LLM 失败有降级策略。
- **安全**：拒绝目录穿越；上传大小限制（单文件 ≤ 200MB）；API Key 等敏感配置持久化于 `api_settings.json`，不硬编码。
- **可观测**：JSON 结构化日志 + 检查点目录，便于复现与排查。

## 4. 安装说明

### 4.1 环境要求

- Python 3.11+
- Node.js 18+
- uv（Python 包管理器）

### 4.2 配置条件

1. **LLM API**：OpenAI、DeepSeek 或自定义 OpenAI 兼容 endpoint。
2. **[Tavily API](https://www.tavily.com)** ：联网检索功能需要注册 API 密钥。
3. **[MinerU API](https://mineru.net)**：非 Markdown 文档转换需要注册 API 密钥）。
4. **本地嵌入模型**：需下载 `bge-small-zh-v1.5` 到 `KnowledgeBase/embedding_model/`。

### 4.3 环境安装

```bash
# 1. 安装 Python 依赖（使用 uv）
uv sync

# 2. 安装前端依赖
cd web && npm install
```

### 4.4 部署运行

**1.构建前端：**

```bash
cd web && npm run build
# 构建产物在 web/dist/，后端会直接静态托管
```

**2.启动后端：**

```bash
# 开发模式：只监听 server/ 和 scr/ 源码，建模产物写入 artifacts/ 不会中断任务
uv run python -m server.dev

# 如不使用 uv，可使用等效命令（不要省略 reload-dir 与 reload-exclude）
uvicorn server.main:app --reload --port 8000 --reload-dir server --reload-dir scr --reload-exclude artifacts

# 常规运行：不启用自动重载
uvicorn server.main:app --host 0.0.0.0 --port 8000
# 访问网址：http://localhost:8000
```
