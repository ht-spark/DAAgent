# DAAgent（数据分析智能体）

> 面向业务问题的自动化数据分析 Agent — 以自然语言与数据文件发起任务，自主完成「理解问题 → 处理数据 → 探索验证 → 解释结果 → 生成报告」

DAAgent 是一款**面向业务问题的自动化数据分析 Agent**，而不是「取数工具 + 看板」或「分析任务 / 知识库问答」两条并行产品线。用户以自然语言问题和数据文件发起分析任务，并可通过知识库先行核对业务资料；系统由大模型围绕当前问题自主规划分析路径，调用代码完成数据处理与验证，最终交付包含图表、结论、证据和审查信息的完整报告。

产品当前以  **「文件驱动的端到端分析」** 为核心：重点解决从已有数据到可信分析交付之间的效率与质量问题，**不替代**企业数据仓库、指标平台或实时 BI。其差异化不在于把自然语言直接翻译成 SQL，也不在于套用固定分析模板，而在于依据具体问题和数据特征动态完成：

**理解问题 → 处理数据 → 探索验证 → 解释结果 → 生成报告**

并通过中间产物与运行轨迹，让过程可监控、可干预、可复现。

## 1. 功能介绍

### 1.1 产品背景

当前企业数据分析的主要问题并不只是工具使用门槛高，而是**整个分析链路存在割裂、重复劳动和协作成本**：

1. **业务问题难以转化为分析问题**：用户往往知道自己关心什么，却难以明确指标口径、对比基准、分析维度和验证方法。
2. **数据查找与获取成本高**：表、字段和数据文档数量多且信息不完整，分析师需要反复找数据、确认关联关系并编写或修改取数代码。
3. **指标口径缺乏统一管理**：同一指标可能存在多种定义，造成跨部门结果不一致，并增加沟通、核验和决策风险。
4. **数据处理占用大量时间**：缺失、重复、异常和延迟等问题依赖人工清洗与校验，真正用于分析判断的时间被持续压缩。
5. **探索式分析响应缓慢**：产品经理和业务运营提出新的维度或原因假设后，通常需要重新向分析师提需求、等待取数并再次分析。
6. **现有工具偏重展示而非解释**：传统 BI 和固定看板擅长回答「发生了什么」，但难以持续下钻并回答「为什么发生、下一步怎么办」。
7. **单点智能能力无法覆盖完整流程**：Text-to-SQL 主要解决取数问题，Notebook 和脚本则依赖专业能力，均未完整覆盖问题澄清、数据处理、探索验证、结论追溯和报告交付。
8. **业务知识与历史分析难以复用**：指标定义、业务说明和历史结论分散在不同文档中，分析时容易缺少上下文，相似问题也需要重复处理。
9. **分析结果与业务决策之间仍有距离**：许多分析止步于指标和图表，未形成从异常发现、原因解释到行动建议的完整链路。

因此，数据分析产品需要从「数据查询与展示工具」升级为 **「面向业务问题的分析执行系统」**：以具体问题为起点，连接数据、业务知识和分析过程，完成从问题澄清、数据处理、探索验证到结论表达的闭环，并允许用户在关键节点介入和核验。

### 1.2 产品目标

- **降低分析门槛与交付周期**：用户提交业务问题和数据文件后，系统自动完成数据理解、清洗、分析、验证与报告生成，减少对 SQL、Python 和统计工具操作经验的依赖。
- **提升分析深度**：不止返回指标和图表，而是围绕业务问题进行趋势、对比、分群、归因等探索，形成从现象、证据到原因解释和行动建议的完整分析链路。
- **保证过程可控、结果可信**：保留中间代码、数据、决策摘要和审查信息，使关键结论可复现、可核验、可追溯；用户可通过追问持续介入。
- **统一并复用业务知识**：通过知识库沉淀指标口径、业务说明和历史分析，为任务提供可引用的上下文，减少重复确认和口径冲突。
- **逐步形成分析知识闭环**：在任务执行与知识检索能力的基础上，后续打通知识加载、任务产出回灌和多轮追问，使一次性分析逐步演进为可持续复用的组织分析能力。

### 1.3 产品定位与边界

| 维度               | DAAgent                                                     |
| ------------------ | ----------------------------------------------------------- |
| **是**       | 面向业务问题的分析执行系统；文件驱动的端到端分析 Agent      |
| **不是**     | 企业数据仓库 / 指标平台 / 实时 BI 的替代品                  |
| **不是**     | 仅做 Text-to-SQL 的取数工具，或套用固定分析模板的报告生成器 |
| **核心差异** | 依据问题与数据特征动态规划路径，代码化分析，中间过程可核验  |

演进路径：**自动完成一次分析 → 接入并复用业务知识 → 支持连续追问与自动下钻 → 关联更多业务上下文**，最终帮助用户从数据变化定位关键原因，并将分析结果转化为可执行的决策依据。

### 1.4 核心能力

用户提交自然语言问题与数据文件后，Agent（项目主体 `data_analysis/`）自主决定是否调用工具、调用哪些工具、何时作答。

**端到端分析闭环：**

```
理解问题（澄清目标、口径、对比基准）
  → 处理数据（画像、清洗、核实记录）
  → 探索验证（趋势/对比/分群/归因等，代码化执行）
  → 解释结果（现象、证据、原因）
  → 生成报告（图表、结论、中间产物）
```

**运行方式：**

```
用户问题 (+数据附件 / 预选知识库)
  → AgentLoop：输出 Action 或 Finish
  → Harness：沙箱/进程内执行工具 → Observation
  → 写回状态 → 再决策 → … → Finish
```

**内置工具（按运行上下文动态注册）：**

| 工具                        | 作用                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------ |
| `profile_data`            | 数据画像：规模、类型、缺失/重复、分布、离群、候选键、时间/空间字段、高相关列               |
| `inspect_data_rows`       | 查看真实数据行，核实字段取值与异常样本                                                     |
| `execute_python`          | 动态 Python 分析；注入`DATA_FILES` / `OUTPUT_DIR` / `ARTIFACTS`，结论写入 `result` |
| `write_artifact`          | 安全写出 Markdown / DOCX / CSV / XLSX / JSON / 代码等产物                                  |
| `inspect_artifact`        | 交付前复核文本与代码产物                                                                   |
| `inspect_generated_image` | 视觉复核图表表达、坐标轴、图例与布局                                                       |
| `inspect_image`           | 识读上传图片中的文字、表格、公式（需视觉模型）                                             |
| `search_knowledge_base`   | 按需检索用户预选知识库，返回`source_file` 供引用                                         |
| `search_web`              | 按需联网检索公开资料，结果注明来源 URL                                                     |

**过程可见与可核验：**

- SSE 实时推送公开决策摘要（`thought`）、工具调用与观察结果，不暴露内部思维链。
- 保留中间代码、数据表、图表与产物文件，关键数字可回溯。
- 知识库结论注明 `source_file`，联网结论注明 URL；数据事实只报告工具结果能支持的内容。

### 1.5 核心场景

1. **AB 测试**：实验组/对照组指标对比与业务解读
2. **竞品分析**：结合上传资料与公开信息的对比研究
3. **需求调研**：基于数据的结论整理与依据梳理
4. **PRD 文档撰写**：为产品文档提供数据结论与图表支撑
5. **周期报告**：日报、周报、月报、季报、年报
6. **日常数据分析**：漏斗分析、DAU、GMV、因果推断、归因分析、指标体系构建等

### 1.6 平台协同

- `server/` 准备附件与产物目录，注入知识库 / 联网等运行上下文，驱动 `data_analysis` 流式执行。
- `web/` 展示分析过程与产物，支持同一会话内连续追问。
- 知识库用于分析前核对口径与复用历史结论；报告回灌知识库等闭环在后续版本打通。

## 2. 面向群体

| 用户类型       | 典型痛点                                          | 核心诉求                                         |
| -------------- | ------------------------------------------------- | ------------------------------------------------ |
| 产品经理       | 不擅长直接取数，新的分析思路依赖分析师再次排期    | 用业务语言发起分析，快速获得可继续验证的原因解释 |
| 数据分析师     | Ad-hoc 需求多，反复找数据、清洗、改代码和制作报告 | 自动完成重复环节，把时间集中在方法判断与业务解释 |
| 业务运营/增长  | 关注转化、留存和活动效果，但缺少独立分析能力      | 从指标变化快速定位关键维度并获得行动建议         |
| 数据团队负责人 | 指标口径不一致，历史分析难复用，结论过程难以追溯  | 规范分析交付，沉淀可核验、可复用的分析资产       |

**典型使用方式：**

- **直接发起分析**：描述业务问题并上传数据文件 → 系统自动理解、处理、探索并生成报告。
- **知识先行**：先在知识库中核对指标口径与历史结论，再带着约束发起分析任务。
- **连续追问**：对结果继续下钻（渠道、地区、用户分群等），在同一会话中迭代验证。
- **周期交付**：按日报/周报等固定节奏，把经营数据整理为可分享的报告与图表。

## 3. 主要技术

### 3.1 设计原则

**产品原则：**

- **面向业务问题，而非面向取数**：交付完整分析链路（现象 → 证据 → 原因解释 → 建议），而不是停在指标和图表。
- **LLM-only 策略**：不预设固定分析方法论或问题类型模板；由大模型围绕具体问题与数据特征动态规划路径。
- **代码化分析、结果可复现**：分析由生成代码在隔离环境执行，中间表与脚本可追溯。
- **过程可控、结果可信**：中间产物与运行轨迹可核验；支持追问式介入，而非黑盒一次性出报告。
- **业务知识可引用**：知识库与联网来源必须可溯源，服务口径对齐与上下文补全。
- **文件驱动、边界清晰**：以用户上传数据为分析起点，不替代数仓、指标平台与实时 BI。

**工程原则：**

- **Loop / Harness 分离**：决策只产出 `Action`/`Finish`，执行层负责权限、沙箱、超时与错误标准化。
- **自主决策**：信息足够时直接作答；仅当工具结果会实质改善答案时才调用工具。
- **路径授权与最小权限**：工具只访问本次运行绑定的文件与产物目录。
- **观察驱动再决策**：工具结果写回状态后必须重新判断下一步。
- **现有能力复用**：知识库检索复用 `KnowledgeBase/`，联网复用 Tavily 封装。

### 3.2 技术栈

| 层次              | 技术选型                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| Agent 决策        | 自研 Loop：结构化 JSON 决策（`action` / `finish`）+ 纠错重试          |
| 运行编排          | `agent/graph.py` 事件流：`iter_graph` / `run_graph`（SSE 友好）     |
| 工具执行          | `Harness` + `SubprocessSandbox`（超时、协议、错误标准化）             |
| 工具注册          | `ToolRegistry` / `ToolSpec`（schema + 上下文绑定，按附件动态注册）    |
| 大模型接入        | OpenAI 兼容 Chat Model（OpenAI / DeepSeek / 自定义 endpoint）             |
| 结构化状态        | Pydantic v2（`AgentState` / `Action` / `Finish` / `Observation`） |
| 会话记忆          | 滚动压缩（`context/rolling_memory.py`：摘要 + 最近原文）                |
| 数值计算 / 可视化 | pandas, numpy, scipy, scikit-learn, matplotlib, seaborn, pulp             |
| 产物导出          | Markdown / DOCX / CSV / XLSX / JSON（`write_artifact` + 安全工作区）    |
| 知识库            | 复用`KnowledgeBase/`：MinerU 转换、BGE + BM25 + RRF 混合检索            |
| 联网检索          | Tavily（服务端密钥，模型侧只传`query`）                                 |
| 服务框架          | FastAPI + Uvicorn，SSE 推送分析过程事件                                   |
| 前端              | React + Vite + TypeScript（过程展示 + 产物列表）                          |
| 测试              | pytest（决策解析、工具、画像、沙箱、滚动记忆等单元测试）                  |

### 3.3 主体架构

```
web/ ──→ server/ ──→ data_analysis.agent.graph.iter_graph
                         │
              ┌──────────┼──────────────────┐
              ▼          ▼                  ▼
         agent/loop  runtime/harness   context/rolling_memory
         (决策)      (执行)            (会话压缩)
              │          │
              ▼          ▼
         tools/registry  runtime/sandbox
              │
    ┌─────────┼──────────┼────────────┬─────────────┐
    ▼         ▼          ▼            ▼             ▼
 data_tools code_tools artifact_*  knowledge_*   web_search
 (画像/取行) (动态代码) (写/查产物) (知识库检索)  (Tavily)
```

**Loop 与 Harness 的边界：**

```
agent/loop.py（决策）                 runtime/harness.py（执行）
─────────────────────                ─────────────────────────
组装 prompt（系统提示+对话+工具表）    权限/路径校验
调 LLM → 解析 Action 或 Finish        超时控制
决策纠错重试、未知工具拒绝            沙箱或进程内调用工具
（不自己执行）                        错误捕获与标准化
                                      返回 Observation(result/error/duration)
```

| 目录/模块                  | 职责                                                                  |
| -------------------------- | --------------------------------------------------------------------- |
| `data_analysis/agent/`   | 决策编排：`loop`（Action/Finish）、`state`、`graph`（事件循环） |
| `data_analysis/context/` | 滚动记忆：token 估算、阈值触发压缩、摘要 + 最近原文                   |
| `data_analysis/runtime/` | 执行运行时：`Harness`、`SubprocessSandbox`、子进程 worker         |
| `data_analysis/tools/`   | 工具实现与注册表：数据、代码、产物、识图、知识库、联网                |
| `data_analysis/prompts/` | System Prompt（角色、工具选择策略、安全与引用规范）                   |
| `data_analysis/tests/`   | 单元测试（agent / runtime / tools / context）                         |
| `KnowledgeBase/`         | 知识库摄入与混合检索（被`search_knowledge_base` 复用）              |
| `server/`                | FastAPI：附件准备、工具上下文注入、SSE 流、产物下载                   |
| `web/`                   | 对话界面：公开决策过程、工具观察、产物面板                            |

**边界说明：**

- `agent/loop.py` 只组装消息并解析决策，**从不执行工具**；`runtime/harness.py` 负责 resolve、沙箱/进程内调用与 `Observation` 标准化。
- `tools/registry.create_agent_tool_registry` 按授权文件、产物目录、知识库 ID、视觉模型与 Tavily Key **动态注册**工具。
- `execute_python` 在子进程中注入 `DATA_FILES` / `DATA_FILE_MAP` / `OUTPUT_DIR` / `ARTIFACTS`，结构化结论通过全局变量 `result` 回传。
- `server/` 通过 `compile_rolling_context` 压缩历史后，把消息、数据路径与产物目录写入 `AgentState`，再驱动 `iter_graph` 流式输出。
- 知识库检索与联网搜索为 **in-process** 工具（不进沙箱），但参数与授权上下文仍由注册表约束。

### 3.4 非功能要点

- **安全**：拒绝目录穿越与未授权路径；产物默认禁止覆盖；API Key（如 Tavily）仅存服务端；动态代码限制读写范围。
- **可靠性**：决策 JSON 纠错重试；工具失败标准化为 `Observation`；沙箱超时与输出上限；最大决策轮数兜底。
- **可控可追溯**：SSE 事件流（started / decision / action / observation / finish）+ 产物列表；关键数字可回到中间表与脚本。
- **性能取向**：工具级超时与输出截断，避免单次调用拖死会话；会话级整体超时由服务端兜底。
- **可测试**：决策解析、注册表、画像、沙箱与滚动记忆均有独立单元测试；LLM 与网络调用可 mock。

## 4. 安装说明

### 4.1 环境要求

- Python 3.11+
- Node.js 18+
- uv（Python 包管理器）

### 4.2 配置条件

1. **LLM API**：OpenAI、DeepSeek 或自定义 OpenAI 兼容 endpoint。
2. **[Tavily API](https://www.tavily.com)** ：联网检索功能需要注册 API 密钥。
3. **[MinerU API](https://mineru.net)**：非 Markdown 文档转换需要注册 API 密钥）。
4. **本地嵌入模型**：需下载 `bge-small-zh-v1.5` 到 `KnowledgeBase/embedding_model/`。

### 4.3 环境安装

```bash
# 1. 安装 Python 依赖（使用 uv）
uv sync

# 2. 安装前端依赖
cd web && npm install
```

### 4.4 部署运行

**1.构建前端：**

```bash
cd web && npm run build
# 构建产物在 web/dist/，后端会直接静态托管
```

**2.启动后端：**

```bash
# 开发模式：只监听 server/ 和 scr/ 源码，建模产物写入 artifacts/ 不会中断任务
uv run python -m server.dev

# 如不使用 uv，可使用等效命令（不要省略 reload-dir 与 reload-exclude）
uvicorn server.main:app --reload --port 8000 --reload-dir server --reload-dir scr --reload-exclude artifacts

# 常规运行：不启用自动重载
uvicorn server.main:app --host 0.0.0.0 --port 8000
# 访问网址：http://localhost:8000
```
