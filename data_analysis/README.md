# 科研数据分析 Agent 项目架构说明

`data_analysis` 用于建设面向科研工作者的通用数据分析 Agent。系统围绕研究问题组织数据理解、统计分析、规律建模、科研绘图、表格生成和论文实验文本写作，并保证结果可复现、结论可追溯。

## 总体结构

```text
data_analysis/
├── agent/       Agent 运行时与通用基础能力
├── research/    科研领域工作流、规则与证据体系
├── analysis/    确定性数据分析和建模能力
├── writing/     基于分析结果生成科研文本
├── execution/   代码执行、任务调度与隔离环境
├── artifacts/   数据、图表、表格和报告产物
├── prompts/     LLM 提示词与阶段指令
└── tests/       单元测试、集成测试和测试数据
```

## `agent/`：Agent Harness

保存与具体科研方法无关的 Agent 通用运行能力。该层负责让模型持续进行“理解任务—选择工具—读取结果—继续决策”，但不直接实现统计方法或科研写作。

### `agent/core/`

Agent 的核心运行循环与状态控制。

主要职责：

- 实现 Agent Loop；
- 管理一次任务的启动、暂停、恢复和结束；
- 控制最大轮数、工具调用次数、时间和费用预算；
- 判断任务完成、等待用户、执行失败或安全阻断等停止原因；
- 协调上下文、模型、工具、状态和事件模块。

### `agent/context/`

负责上下文工程，决定每次模型调用时向模型提供哪些信息。

主要职责：

- 根据当前工作阶段构建模型上下文；
- 加载研究问题、实验设计和当前分析计划；
- 选择相关 Skill 和提示词；
- 压缩历史消息和冗长工具结果；
- 控制上下文长度和 Token 预算；
- 保留已确认事实、关键结果和未解决问题。

### `agent/events/`

定义和分发 Agent 运行期间的事件。

典型事件包括：

- Agent 或任务开始；
- 数据检查完成；
- 请求用户确认；
- 工具执行开始、更新和结束；
- 分析或模型运行完成；
- 图表、表格或报告生成；
- 验证警告、失败和最终完成。

这些事件可用于前端实时进度、日志、调试、任务恢复和性能评测。

### `agent/providers/`

封装不同大语言模型供应商的接口差异。

主要职责：

- 提供统一的模型调用接口；
- 转换不同供应商的消息格式；
- 适配流式输出、工具调用和结构化输出；
- 管理模型能力、推理等级和使用量；
- 使科研业务逻辑不依赖某个具体模型。

### `agent/tools/`

保存 Agent 工具协议、注册表和调用策略，不放具体统计实现。

主要职责：

- 定义工具名称、说明和输入输出 Schema；
- 注册、发现和选择工具；
- 按工作阶段限制允许调用的工具；
- 区分只读工具和有副作用的工具；
- 管理工具超时、重试和执行结果；
- 在工具调用前后执行权限与结果检查。

## `research/`：科研领域核心

保存科研 Agent 区别于普通数据分析工具的核心能力，包括实验设计、科研工作流、统计规范、证据追踪和质量验证。

### `research/schemas/`

定义科研项目的结构化数据模型。

可以包含：

- 研究问题；
- 研究假设；
- 实验设计；
- 独立实验单位；
- 生物学重复、技术重复和重复测量；
- 自变量、因变量、协变量和批次变量；
- 数据集与数据版本；
- 分析计划和分析结果；
- 科研结论与证据关系。

该目录中的 Schema 是各模块交换信息的统一协议。

### `research/workflows/`

定义科研分析的显式工作流和状态转换。

典型流程为：

```text
接收任务
→ 数据画像
→ 理解实验设计
→ 确认分析计划
→ 数据处理
→ 统计或建模
→ 结果验证
→ 图表与表格
→ 论文文本
→ 一致性审查
→ 最终交付
```

工作流负责规定进入条件、退出条件、允许工具、验证要求和失败恢复路径。

### `research/skills/`

保存按需加载的科研专业能力说明。

例如：

- 实验设计识别；
- 描述性统计；
- 组间比较；
- 重复测量分析；
- 回归与预测建模；
- 科研绘图；
- 统计方法和 Results 写作；
- 统计结果审查。

Skill 提供方法选择规则、操作步骤、红线和输出要求，但数值计算仍由确定性分析工具完成。

### `research/validators/`

负责科研质量验证。

主要检查：

- 方法是否匹配实验设计；
- 独立实验单位和样本量是否正确；
- 是否混淆技术重复与独立重复；
- 是否正确处理配对、嵌套和重复测量；
- 是否需要多重比较校正；
- 模型假设、诊断和收敛情况；
- 是否将相关关系错误解释为因果关系；
- 图、表和论文文本中的数字是否一致；
- 结论是否超出数据支持范围。

### `research/evidence/`

管理“研究问题—数据—分析—结果—图表—论文结论”的证据链。

主要职责：

- 为每次分析和结果分配稳定标识；
- 记录结果来自哪个数据版本和哪段代码；
- 将图表面板、结果表和文本句子关联到统计结果；
- 保存结论的适用范围和限制；
- 支持结果追溯、一致性检查和重新计算。

## `analysis/`：确定性分析能力

保存真正读取数据、执行计算和产生数值结果的程序。LLM 可以选择分析方法和解释结果，但不能代替该层产生统计数字。

### `analysis/data/`

负责数据读取、理解、清洗和转换。

主要职责：

- 读取 CSV、XLSX 等数据；
- 识别字段、类型和单位；
- 生成数据画像；
- 检查缺失值、重复值和异常值；
- 处理宽表、长表和表间关系；
- 保存清洗步骤与数据版本；
- 防止静默覆盖原始数据。

### `analysis/statistics/`

负责传统统计分析。

可以包含：

- 描述性统计；
- 两组和多组比较；
- 配对分析；
- 重复测量；
- 相关分析；
- 线性和广义线性模型；
- 效应量与置信区间；
- 多重比较校正；
- 模型假设和残差诊断。

所有方法应返回结构化结果，而不是只返回自然语言。

### `analysis/modeling/`

负责规律发现、预测和数学建模。

可以包含：

- 回归与非线性拟合；
- 分类和预测；
- 聚类与降维；
- 时间序列；
- 参数估计；
- 特征重要性；
- 灵敏度和稳健性分析；
- 候选模型比较和基线评估。

该层延续 MMAgent 的建模优势，但模型选择应根据研究问题进行，避免固化问题分类和方法组合。

### `analysis/visualization/`

负责生成科研风格图表。

主要职责：

- 根据科学问题和证据关系选择图形；
- 绘制统计图、拟合图、诊断图和多面板图；
- 管理科研配色、字体、尺寸和图例；
- 检查误差线、样本点和统计标注；
- 导出 PNG、SVG、PDF 或 TIFF；
- 保存绘图代码和图源数据；
- 对最终渲染结果进行布局检查。

### `analysis/tables/`

负责生成科研结果表和可视化表格。

主要职责：

- 生成描述统计表；
- 生成模型参数、效应量和比较结果表；
- 控制数值精度和缺失值表示；
- 导出 CSV、XLSX、Markdown、LaTeX 或 Word 表格；
- 确保表格数字来自结构化分析结果。

## `writing/`：科研文本生成

根据真实分析结果生成论文相关文本。该层只负责表达，不重新计算或修改统计结果。

### `writing/methods/`

负责生成数据处理、统计分析和建模方法文本。

内容可以包括：

- 数据预处理方式；
- 变量和实验单位定义；
- 使用的统计检验或模型；
- 多重比较方法；
- 模型诊断；
- 软件、版本、主要参数和随机种子。

缺失信息应明确标记并请求作者补充，不能自行编造。

### `writing/results/`

负责生成论文 Results 或实验分析文本。

主要职责：

- 从结构化结果提取可报告发现；
- 绑定效应量、区间、样本量和检验结果；
- 控制结论措辞强度；
- 区分观察、关联、预测和因果证据；
- 避免只围绕显著性组织结果；
- 保持结果段落与图、表一致。

### `writing/captions/`

负责生成图注和表注。

图注和表注应说明：

- 图表展示的对象；
- 分组和实验条件；
- 点、线、箱体和误差线的含义；
- 样本量及其定义；
- 使用的统计方法；
- 显著性符号或区间的含义。

## `execution/`：安全执行与调度

负责运行分析代码和管理耗时任务。

### `execution/sandbox/`

负责隔离执行 Python 或未来的 R 分析代码。

主要职责：

- 为每次任务创建独立工作目录；
- 限制可读写路径；
- 控制网络访问；
- 限制 CPU、内存和运行时间；
- 捕获输出、错误和退出码；
- 校验生成文件路径；
- 保存依赖、运行环境和复现信息。

### `execution/jobs/`

负责任务排队和异步执行。

适用于：

- 大文件解析；
- 模型拟合；
- 参数搜索；
- Bootstrap 或重复实验；
- 批量绘图；
- 文档渲染和质量审查。

该目录还负责任务取消、超时、重试、崩溃恢复和进度更新。

## `artifacts/`：运行产物

保存科研任务生成的文件。所有写入路径都应经过校验，并按项目、数据版本和运行编号组织。

### `artifacts/datasets/`

保存：

- 上传的原始数据副本；
- 清洗后的数据；
- 用于绘图的源数据；
- 数据字典；
- 数据转换和版本信息。

### `artifacts/figures/`

保存：

- 科研图预览；
- SVG、PDF、TIFF 等投稿文件；
- 多面板组合图；
- 绘图源代码；
- 图形质量检查结果。

### `artifacts/tables/`

保存：

- 描述统计表；
- 统计检验结果表；
- 模型结果表；
- 可用于论文或补充材料的导出表格。

### `artifacts/reports/`

保存：

- Markdown 或 HTML 分析报告；
- DOCX、LaTeX 或 PDF 文档；
- Statistical Analysis 和 Results 文本；
- 完整分析包及交付清单。

## `prompts/`：提示词资源

按照稳定规则、工作阶段和专业能力分开保存提示词，避免在 Python 代码中嵌入大段提示词。

### `prompts/core/`

保存长期稳定的核心规则，例如：

- Agent 身份和职责；
- 科研诚信要求；
- 工具使用原则；
- 禁止编造数字；
- 证据与结论边界；
- 完成条件和停止规则。

### `prompts/stages/`

保存不同工作阶段的提示词，例如：

- 任务接收；
- 数据画像；
- 实验设计确认；
- 分析计划；
- 分析执行；
- 结果验证；
- 最终交付。

### `prompts/skills/`

保存与 `research/skills/` 配套的可复用提示片段。只有当前任务需要时才加载，避免将全部科研规则塞入模型上下文。

## `tests/`：测试与评测

### `tests/unit/`

保存单元测试，验证单个模块的确定性行为。

重点覆盖：

- Schema 校验；
- 工具参数和结果；
- 状态转换；
- 上下文选择；
- 数据处理函数；
- 统计结果计算；
- 异常和格式错误边界。

### `tests/integration/`

保存跨模块和端到端测试。

典型场景：

- 从上传数据到分析结果；
- 从分析结果到图表和论文文本；
- 工具失败后的恢复；
- 用户确认后的任务继续；
- 图、表、文字一致性；
- 完整科研分析闭环。

测试应模拟模型和网络请求，不依赖真实 API Key。

### `tests/fixtures/`

保存测试专用输入和标准答案，例如：

- 小型 CSV/XLSX 数据；
- 实验设计样例；
- 标准统计结果；
- 故意包含错误的数据；
- LLM 工具输出样例；
- 图表和报告预期元数据。

该目录的数据不应包含真实用户隐私或未公开科研数据。

## 模块协作关系

```text
用户请求
  ↓
agent/core 调度任务
  ↓
agent/context 构建当前上下文
  ↓
agent/providers 调用模型
  ↓
agent/tools 选择并执行工具
  ↓
research/workflows 控制科研步骤
  ↓
analysis 产生真实计算结果
  ↓
research/validators 检查科研质量
  ↓
research/evidence 建立证据关系
  ↓
writing 生成论文相关文本
  ↓
artifacts 保存最终交付物
```

## 开发边界

1. `agent/` 不包含具体统计方法。
2. `analysis/` 不负责调用 LLM 或撰写论文结论。
3. `writing/` 不自行计算或修改统计数字。
4. `research/evidence/` 是图、表、文字共用的结果来源。
5. `execution/` 负责安全运行，不决定科研方法。
6. `prompts/` 保存提示词，避免在业务代码中嵌入大段文本。
7. `artifacts/` 只保存经过路径校验的运行产物。
8. 新功能应优先实现为工具、Skill、验证器或工作流节点，避免不断扩大主 Agent Loop。
