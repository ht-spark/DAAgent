## Design Specificity Verdict

**LLM 评估**：通用 B 端外壳 + 少数真产品化区块。结构层（固定侧栏 + page-head + 卡片/表格 + api-modal）可以整体搬到任何后台产品：`KnowledgeBaseHistory`、`DocConverter`、`Skills`、`ApiManager` 四页近乎同构，没有产品指纹。真正的产品性格只出现在 `ChatModeling.tsx` 的 `TaskWorkflow`（求解流水线 + 节点级 ✓ + 实时 token/耗时）与 `TaskExpert` 的 `ExpertEditor`（总览卡片 → 板块聚焦 + 未填写/待完善/已就绪徽标，渐进披露做对了）。最大的浪费是「可核验」——产品唯一的差异点——恰好被默认藏起来：报告以裸文本呈现，运行轨迹默认收起，run.log 面板名存实亡。

**确定性扫描**：`detect --json web/src` 退出码 **2**，共 **17 条**，全部落在 CSS（forms.css 13 / index.css 4），TSX 命中 0 条。分组：side-tab 8｜layout-transition 4｜gradient-text 2｜overused-font 1｜border-accent-on-rounded 1｜bounce-easing 1。逐条位置：forms.css 2883 / 4715 / 5211 / 10447 / 10782 / 10849（side-tab）；index.css 886 / 674（side-tab）；forms.css 6871（border-accent-on-rounded）、6414（overused-font）、4885（bounce-easing）、585 / 4272 / 7958 / 8486（layout-transition）；index.css 402 / 1330（gradient-text）。

交叉验证：检测器的 4 条 `layout-transition` 与 A 的「动画化布局属性」判断互为印证。但检测器**没有**覆盖 A 报出的死 CSS、run.log 死面板、中英混排、`aria-hidden` 焦点问题——规则集只识别视觉模式，这几项是人工审查独有的价值。判定为误报的条目：forms.css:4885 `bounce-easing`（规则按动画名子串命中，实际曲线是 `ease-in-out`，keyframe 只动 opacity/transform）；forms.css:585 `layout-transition`（侧栏拖拽宽度的必要过渡，属设计意图）。

## Overall Impression

这是一套「工程上比设计上更成熟」的界面。模态栈、`prefers-reduced-motion` 覆盖（12 处）、`contain` 隔离、SSE 流水线这些底层细节做得比多数 B 端产品好；但产品主张与界面呈现是脱节的——它对外承诺「过程可控、结果可信、可复现」，而界面上唯一能兑现这三个词的两处证据（Markdown 报告、运行日志）一处裸文本、一处是死面板。最大的机会点不是加新功能，而是把已经算出来的东西如实呈现出来。

## What's Working

1. **`TaskWorkflow` 求解流水线**（ChatModeling.tsx:347）：节点级 ✓、实时 token 与耗时，把 LLM 黑箱转成可观察过程，正对 Operate 诉求，也是全站最具产品指纹的一处。
2. **`pushModalLayer` 统一模态栈**（modalLayer.ts）：Esc 只作用最上层、统一滚动锁、弹窗打开时暂停氛围动画，工程与体验同时收敛。
3. **`ExpertEditor` 渐进披露**（TaskExpert.tsx）：总览卡片 → 板块聚焦 + 三态徽标 + 逐字段 hint，把「配置一个专家」这种高认知负荷任务切成了可消化的小步。

## Priority Issues

### 1. [P1] 中英混排 + 产品名自相矛盾
- **What**：作曲栏可见英文 `Select model`（NewChat.tsx:2245）、`No model configured`（NewChat.tsx:2312）；档位值直接渲染英文 `思考程度 close / xhigh / max`（NewChat.tsx:2270，取值见 apiConfigs.ts:21-28）；`apiConfigs.test.ts:15` 用断言把「标签等于英文值」锁死，等于把问题固化成规范。同时 `ChatModeling.tsx:593` 欢迎语写「MMAgent 建模助手」，而侧栏与 `<title>` 都是 DAAgent。
- **Why it matters**：目标用户是产品经理/运营/分析师，`xhigh`、`close` 无任何可理解性；产品名矛盾直接伤害「可信」这一核心卖点——用户无法确认自己在用哪个产品。
- **Fix**：全站统一中文词汇：档位改「关闭/低/中/高/极高/最大」，同步更新 `apiConfigs.ts` 的 label 与测试断言；`Select model`→「选择模型」，`No model configured`→「未配置模型」；欢迎语统一为 DAAgent。
- **Suggested command**：`$impeccable clarify`

### 2. [P1] 「可核验」被默认藏起来（含一处撒谎的 UI）
- **What**：`Result.tsx:59-60` 标题写「报告预览（Markdown）」，实现却是 `<pre className="paper-box">{paper}</pre>` 裸文本——项目里已有 `MarkdownContent` 组件且装了 rehype-katex/remark-gfm，能力完全具备却没用上。`ChatModeling.tsx:340-341` 的 run.log 面板永远显示「等待运行日志写入…」：`runLog` 只在 ChatModeling.tsx:617 被重置为 `''`，`setRunLog` 从未写入过内容，`api.ts:212-214` 的 `readRunLog` 也未从该页调用。
- **Why it matters**：这两个位置正是产品差异点（可核验、可复现）的唯一载体。死面板比缺功能更糟——它向用户暗示"日志本来会有"，长期损害信任。
- **Fix**：报告改为 `MarkdownContent` 渲染，去掉内联 `style={{fontSize:16}}`；run.log 二选一——要么实现轮询写入，要么删掉面板，绝不能保留假装工作的状态。
- **Suggested command**：`$impeccable harden`

### 3. [P1] 每个页面都背着一整页营销站 CSS
- **What**：`index.css` 共 1,463 行，其中约 1,100 行是 `.hero`、`.cta`、`.footer`、`.cap-card`、`.models-grid`、`.demo-container`、`.data-table`、`.float-card`、`.workflow-steps` 等落地页样式；`web/index.html` 只有 `<div id="root">`，全项目 TSX 对这些类名 **0 引用**（grep 无命中）。同一文件头部还写着「MMAgent - 数学建模智能体 / 科技风 · 淡蓝色主题」，与现在暖黄 DAAgent 主题直接矛盾。
- **Why it matters**：约 40KB 无用 CSS 随每次请求下发；更贵的是认知成本——后来者无法判断 `:root` 里哪些 token 可信、哪些是上一版产品的遗留。
- **Fix**：删除落地页区块，`index.css` 只保留 `:root` 令牌 + 背景层 + 全局 reset，并同步修正文件头注释。
- **Suggested command**：`$impeccable distill`

### 4. [P2] 氛围背景是上一版产品的遗留噪声
- **What**：`App.tsx:32` 的 `SYMBOLS`（∫ ∑ ∏ ∂ ∇ ∞ π σ μ λ α β γ θ Δ Ω）经 `.floating-symbols` 全屏常驻浮动，`.bg-glow` 12s 无限循环（index.css:105）。这些是数学建模产品的装饰，对数据分析用户不承载任何信息。浏览器实测确认所有页面均可见。
- **Why it matters**：Operate 界面上 18 个持续运动的符号只增加合成开销与视觉噪声，也是第 8 条只给 2 分的主因。
- **Fix**：Operate 页面移除符号层，仅保留静态网格与渐变；若必须保留品牌氛围，改为不循环的一次性入场，并在 `prefers-reduced-motion` 下彻底关闭。
- **Suggested command**：`$impeccable quieter`

### 5. [P2] 同一份运行数据有两套界面实现
- **What**：`ChatModeling.tsx` 中 `TaskWorkflow`(347) 与 `RunMonitorPanel`(279) 接收同一组 props（run / monitor / now / phase / currentStep），分别从 1202 与 1506 渲染。同一动作在界面上有四种叫法：中断、终止、终止运行、终止任务。
- **Why it matters**：时间线口径与文案会持续漂移，任何改动都要记得改两处，是最典型的可维护性税。
- **Fix**：合并为一套运行视图；若两种模式确有差异，则抽出公共子组件，只让外层布局分叉。
- **Suggested command**：`$impeccable distill`
